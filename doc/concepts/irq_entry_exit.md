# Вход и выход из IRQ-обработчика

> [!abstract] Суть
> Вектор IRQ — это 128 байт, куда помещается только переход. Настоящая работа — в trampoline: сохранить GPR, вызвать Rust-функцию, восстановить GPR, вернуть управление через `eret`. Обработчик обязан вернуться, а не паниковать: иначе прерванный код не продолжится.

## Что делает CPU при входе в IRQ

1. `PC` → `ELR_EL1` (адрес следующей инструкции прерванного кода).
2. `PSTATE` → `SPSR_EL1`.
3. `PSTATE.I ← 1` (IRQ маскируются, вложенности нет).
4. `PC ← VBAR_EL1 + 0x280` (current EL, SPx, IRQ).
5. `SP` остаётся прежним — обработчик работает на стеке прерванного кода.

`ESR_EL1` при IRQ **не обновляется**: класс исключения известен из слота вектора. Не пытайтесь в IRQ-обработчике декодировать `ESR_EL1` как причину IRQ.

## Почему trampoline

128 байт слота не хватает на сохранение 31 регистра. Поэтому в слоте — только `b irq_handler_asm`, а сохранение и восстановление — в отдельной метке после таблицы.

## Кадр стека

Простейший вариант — сохранить все `x0–x30` и `ELR/SPSR`:

```text
sp + 0    x0, x1
sp + 16   x2, x3
...
sp + 224  x28, x29
sp + 240  x30, xzr
sp + 256  ELR_EL1, SPSR_EL1
итого 272 байта (17 × 16) — SP остаётся 16-байтно выровненным
```

По AAPCS64 Rust-функция обязана сохранить `x19–x29` и `SP`, но не обязана сохранять `x0–x18` и `x30`. Проще сохранить всё: 272 байта на 64-КБ стеке — ничто, зато нет шансов забыть регистр.

## Скелет

```asm
// слот
SLOT irq_handler_asm

irq_handler_asm:
    sub sp, sp, #272
    stp x0,  x1,  [sp, #0]
    stp x2,  x3,  [sp, #16]
    stp x4,  x5,  [sp, #32]
    stp x6,  x7,  [sp, #48]
    stp x8,  x9,  [sp, #64]
    stp x10, x11, [sp, #80]
    stp x12, x13, [sp, #96]
    stp x14, x15, [sp, #112]
    stp x16, x17, [sp, #128]
    stp x18, x19, [sp, #144]
    stp x20, x21, [sp, #160]
    stp x22, x23, [sp, #176]
    stp x24, x25, [sp, #192]
    stp x26, x27, [sp, #208]
    stp x28, x29, [sp, #224]
    stp x30, xzr, [sp, #240]

    mrs x0, elr_el1
    mrs x1, spsr_el1
    stp x0, x1, [sp, #256]

    bl irq_handler          // Rust, возвращается

    ldp x0, x1, [sp, #256]
    msr elr_el1, x0
    msr spsr_el1, x1

    ldp x0,  x1,  [sp, #0]
    ldp x2,  x3,  [sp, #16]
    ldp x4,  x5,  [sp, #32]
    ldp x6,  x7,  [sp, #48]
    ldp x8,  x9,  [sp, #64]
    ldp x10, x11, [sp, #80]
    ldp x12, x13, [sp, #96]
    ldp x14, x15, [sp, #112]
    ldp x16, x17, [sp, #128]
    ldp x18, x19, [sp, #144]
    ldp x20, x21, [sp, #160]
    ldp x22, x23, [sp, #176]
    ldp x24, x25, [sp, #192]
    ldp x26, x27, [sp, #208]
    ldp x28, x29, [sp, #224]
    ldp x30, xzr, [sp, #240]
    add sp, sp, #272
    eret
```

`eret` берёт адрес из `ELR_EL1` и PSTATE из `SPSR_EL1`. Обычный `ret` здесь не годится: он вернётся в trampoline, а не в прерванный код.

## Rust-обработчик

```rust
#[unsafe(no_mangle)]
extern "C" fn irq_handler() {
    let iar = read_icc_iar1_el1();
    let intid = iar & 0xFFFFFF;

    if intid == 1023 {
        return;                 // spurious: EOI не пишем
    }

    if intid == TIMER_INTID {
        unsafe { write_cntv_tval(freq() / 4); } // погасить источник
        TICKS.fetch_add(1, Ordering::Relaxed);
    }

    unsafe { write_icc_eoir1_el1(iar); }        // EOI после гашения
}
```

Правила:
- `extern "C"` и обычный возврат `()` — asm ждёт `ret`.
- Не печатать в UART из ISR: опрос `FR` может занять время, а обработчик должен быть коротким. Печать — в `main` по счётчику.
- Счётчик — `AtomicU32` с `Ordering::Relaxed`: атомарность нужна, порядок памяти — нет. Это мост к этапу 4.
- `spurious (1023)` — не писать EOI: прерывания не было.

## Вспомогательные функции

`read_icc_iar1_el1` — тонкая обёртка над `mrs`: в Rust нет стабильного интринсика для системных регистров, только `asm!`.

```rust
fn read_icc_iar1_el1() -> u64 {
    let v;
    unsafe { core::arch::asm!("mrs {}, icc_iar1_el1", out(reg) v) };
    v
}
```

- `IAR` = Interrupt Acknowledge Register. Полезный INTID — в битах `[23:0]`; `1023` — spurious.
- **Чтение IAR — не «просто чтение»**: оно подтверждает (acknowledge) прерывание и снимает его из pending. Поэтому нельзя помечать функцию `options(pure)` или вызывать её дважды за обработчик: второе чтение «съест» следующее прерывание.
- Запись в `ICC_EOIR1_EL1` — парная операция; пишем то же значение, что прочитали из IAR (для не-SGI достаточно INTID).
- `ticks()` и `TICKS` — см. [[atomic_counter]].

## Подводные камни

> [!warning]
> - Забыли `eret` → после обработчика CPU уйдёт в мусор (или в `ret`-адрес).
> - Не сохранили `x0–x18` → прерванный Rust-код получит испорченные значения, баг «плавающий», зависит от места прерывания.
> - Не выровняли SP → `stp`/`ldp` и вызов Rust могут дать fault по выравниванию.
> - Обработчик `-> !` (паника) → система встанет на первом же тике; для IRQ нужен возврат.
> - Включили FP/SIMD (`CPACR_EL1.FPEN`) и не сохранили `q0–q31` → тихая порча вычислений. Сейчас FP не используется, но при переходе на `f32`/`f64` это станет обязательным.
> - `ESR_EL1` в IRQ не обновляется — не путать с sync-исключениями.
> - Вложенные прерывания: по умолчанию `PSTATE.I=1` на входе. Если захотите вложенность, нужно сохранять `ELR/SPSR` и аккуратно снимать маску — это отдельный шаг.
