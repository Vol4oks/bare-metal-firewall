# Барьеры AArch64: DSB, DMB, ISB

> [!abstract] Суть
> `volatile` запрещает оптимизации компилятора, но не управляет порядком обращений на уровне CPU. Для этого есть барьеры: `DMB` упорядочивает, `DSB` ждёт завершения, `ISB` сбрасывает конвейер и заставляет CPU увидеть новое состояние системы.

## Три инструкции

| Инструкция | Гарантия | Не делает | Типичный случай |
|---|---|---|---|
| `DMB sy` | порядок: обращения до барьера видны раньше обращений после | не ждёт завершения | публикация данных, lock-free |
| `DSB sy` | ждёт завершения всех предыдущих обращений к памяти | не сбрасывает конвейер | MMIO: запись → чтение статуса; таблицы MMU; GIC |
| `ISB` | сбрасывает конвейер, последующие инструкции читаются в новом контексте | не ждёт завершения памяти | после `msr` в `SCTLR`/`TTBR`/`VBAR`/`DAIF` |

`sy` — full system. Другие домены: `ish` (inner shareable), `osh`, `nsh`.

## Зачем `dsb sy` после записи в GICR_WAKER

```rust
write_volatile(GICR_WAKER, waker & !(1 << 1));
asm!("dsb sy");
while read_volatile(GICR_WAKER) & (1 << 2) != 0 { ... }
```

- `write_volatile` — только компиляторная гарантия: он не выкинет и не переставит доступ. CPU всё равно может буферизовать запись.
- Наш регион GIC отображён как **Device-nGnRE** (`MAIR=0x04`). `E` = early write acknowledge: запись может быть подтверждена до того, как реально дойдёт до устройства.
- `DSB` гарантирует, что запись завершена, и только потом выполняется чтение. Без него на железе можно прочитать старый `ChildrenAsleep` и уйти в ложный таймаут. В QEMU барьеры почти не моделируются, поэтому баг проявится только на плате.

## Где ещё нужны

- **Включение MMU**: после записи `TTBR0/TCR/MAIR` — `dsb sy`; после `SCTLR.M=1` — `isb`, чтобы следующие инструкции выбирались уже с новой трансляцией.
- **VBAR_EL1**: после `msr vbar_el1` полезен `isb`, чтобы новое значение точно использовалось при следующем исключении.
- **DAIF**: после `msr daifclr/daifset` полезен `isb`, чтобы изменение маски вступило в силу до следующей инструкции.

## Подводные камни

> [!warning]
> - `volatile` ≠ барьер. Это две разные гарантии: компилятор и CPU.
> - `DSB` не сбрасывает кэши. Это не `dc ivac`/`ic ialluis`; он лишь ждёт завершения операций.
> - `DMB` не ждёт завершения: если нужен факт «запись дошла», нужен `DSB`.
> - После изменения системного регистра, влияющего на исполнение, одного `DSB` мало — нужен `ISB`.
> - `DSB sy` в горячем пути (на каждый пакет) может быть дорогим; в init — нормально.
> - В QEMU отсутствие барьера часто не видно; проверять на железе.
