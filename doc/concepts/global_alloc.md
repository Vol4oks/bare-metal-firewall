# GlobalAlloc: договор языка и аллокатора

> [!abstract] Суть
> `GlobalAlloc` — единственная точка, через которую `Box`/`Vec` получают память в `no_std`. Трейт unsafe: ответственность за валидность указателей, выравнивание и Sync — на реализации. Bump-аллокатор легален с пустым `dealloc`: «ничего не делать» — корректное поведение при неиспользуемой памяти.

## Кто кого вызывает

```mermaid
flowchart LR
    A["Box::new(42)"] --> B["alloc::alloc(Layout)"]
    B --> C["#[global_allocator] — наша статика"]
    C --> D["bump: выровнять, сдвинуть ptr"]
```

`Layout` = size + align (align — всегда степень двойки). Выравнивание вверх: `(ptr + align - 1) & !(align - 1)` — работает только для степеней двойки.

## Контракт unsafe

| Обещание | Нарушение |
|---|---|
| валидный указатель на size байт, выровненный на align, либо null | NULL-deref, порча памяти |
| указатели только внутри пула | тихая порча за границей |
| dealloc корректен (для bump — осознанное «ничего») | double free, UAF |
| Sync | гонки |

`&self` + интерьерная мутабельность (`UnsafeCell`) + `unsafe impl Sync` с инвариантом «одно ядро, IRQ замаскированы» — тот же паттерн, что у UART ([[0002_global_uart_handle]]).

## Bump-аллокатор
- `alloc`: выровнять текущий указатель, сдвинуть на size, свериться с `__heap_end`, при выходе — `null_mut()` (не паника).
- `dealloc`: пустой — память не переиспользуется (утечки при активной работе — известная цена этапа).
- `realloc` в трейте нет: `Vec` растёт через alloc нового + копию + dealloc старого.

> [!warning] Подводные камни
> - Забыть выравнивание → unaligned-доступ, на Device-памяти — fault.
> - Паника внутри аллокатора → каскад (паника при печати паники).
> - Отказ должен быть null, а не abort: вызывающий (Vec) сам решает, что делать.
