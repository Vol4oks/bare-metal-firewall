# Одно ядро сейчас, четыре потом

> [!abstract] Суть
> Сейчас код исполняет только ядро 0: остальные припаркованы ([[entry_hygiene]]), прерывания замаскированы. Это инвариант «одного контекста исполнения» — он упрощает весь код до этапа 4. SMP включается после спинлоков (этап 4); цель для файрвола — вынести обработку пакетов на отдельное ядро.

## Почему сейчас одно ядро
- парковка в `_start` + PSCI-удержание вторичных ядер в QEMU/U-Boot+TF-A;
- `daifset` — нет даже прерываний;
- один контекст → не нужны блокировки и барьеры: меньше ошибок на старте.

## Что уже сделано «под SMP»
- парковка в `_start` — готовая точка входа для будущих вторичных ядер;
- `-smp 4` в QEMU — полигон на 4 ядра ([[qemu_adaptation]]).

## Что понадобится для SMP (не сейчас)

| Что | Когда |
|---|---|
| SpinLock/атомики + барьеры памяти | этап 4 |
| Протокол пробуждения ядер (mailbox + `wfe`/`sev` или PSCI `CPU_ON`) | этап 5+ |
| Per-core стеки (сейчас один 64 КБ — корректно, пока ядра спят) | этап 5 |
| Per-core GICv3-редистрибьюторы, таймер | этап 3 (проектировать под N ядер) |
| Per-CPU данные | этап 5+ |

## Правило для кода сейчас
Писать модули (UART, позже heap) так, чтобы добавление блокировки **не меняло их API**: инкапсуляция в структуру, методы с `&mut self`, один глобальный хэндл с изменяемостью за задокументированным инвариантом «одно ядро, IRQ замаскированы» — до этапа 4, когда обернём в SpinLock.

> [!question] Для самопроверки

> - Чем протокол `mailbox + wfe` отличается от PSCI `CPU_ON`?
