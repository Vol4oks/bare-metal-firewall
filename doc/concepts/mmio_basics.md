# Rust-инструментарий MMIO

> [!abstract] Суть
> Вся работа с регистрами в проекте — две функции: `read_volatile` и `write_volatile` (или методы сырых указателей) плюс `usize`-арифметика адресов. Этот же набор закрывает UART, GIC, таблицы страниц и таймер — меняются только смещения и ширина типа.

## Ядро

| Функция / метод | Сигнатура (упрощённо) | Роль |
|---|---|---|
| `core::ptr::read_volatile` | `unsafe fn read_volatile<T>(src: *const T) -> T` | чтение регистра (например, FR) |
| `core::ptr::write_volatile` | `unsafe fn write_volatile<T>(dst: *mut T, val: T)` | запись в регистр (например, DR) |

Методная форма (идиоматичнее): `ptr.read_volatile()`, `ptr.write_volatile(val)`.

Адрес регистра = `base + смещение`, приведение: `(self.base + 0x18) as *const u8`.
`*const` — только чтение, `*mut` — запись; обе операции `unsafe` (инвариант «адрес — настоящий регистр» гарантирует конструктор драйвера).

Опционально: `core::hint::spin_loop()` в тело цикла опроса — на AArch64 компилируется в `yield` (`hint #0`): на SMT-ядрах отдаёт ресурсы соседнему потоку, на A55 фактически NOP. Ценность — самодокументация цикла и нулевая цена; не путать с `wfe` — настоящим энергосберегающим ожиданием до события (протокол пробуждения ядер, этап 5, [[multicore_path]]).

> [!warning] Подводные камни
> - Без `volatile` оптимизатор кэширует/выносит чтение — цикл опроса зависает ([[uart_pl011]]).
> - Для ширины больше байта (`u32` на GIC) адрес обязан быть выровнен на размер: читаем `u32` — адрес кратен 4.
> - `volatile` не даёт атомарности и не синхронизирует ядра — это только запрет оптимизаций доступа; для SMP позже понадобятся атомики ([[multicore_path]]).

## Осознанно НЕ используем сейчас
- `addr_of!` / `addr_of_mut!` — позже, для статических регистровых блоков;
- крейты-обёртки (`vcell`, `tock-registers`) — сначала руками;
- `u32` вместо `u8` на PL011 — байтовый доступ разрешён TRM.
