# Context switch

> [!abstract] Суть
> Cooperative switch сохраняет callee-saved регистры, `x30` и `SP`, затем загружает контекст следующей задачи и делает `ret`. Preemptive switch сложнее: IRQ-trampoline уже сохранил полный контекст, нужно переключить стек на кадр следующей задачи и вернуться через `eret`.

## Cooperative switch

`TaskContext`:

```rust
#[repr(C)]
pub struct TaskContext {
    pub x19: u64,
    pub x20: u64,
    pub x21: u64,
    pub x22: u64,
    pub x23: u64,
    pub x24: u64,
    pub x25: u64,
    pub x26: u64,
    pub x27: u64,
    pub x28: u64,
    pub x29: u64,
    pub x30: u64,
    pub sp: u64,
}
```

Почему только эти регистры:

- `x19–x29` — callee-saved по AAPCS64; вызываемый обязан их сохранить.
- `x30` — адрес возврата после `bl sched_switch`.
- `SP` — стек задачи.
- `x0–x18` — caller-saved: компилятор не ждёт, что они переживут вызов.
- `NZCV` — флаги тоже не переживают обычный вызов.
- `x18` — платформенный регистр; если target его не резервирует, лучше сохранять.
- FP/SIMD — пока не используются; если включишь, нужно сохранять `q0–q31` или хотя бы callee-saved часть.

Скелет asm:

```asm
// x0 = &current.ctx, x1 = &next.ctx
sched_switch:
    stp x19, x20, [x0, #0]
    stp x21, x22, [x0, #16]
    stp x23, x24, [x0, #32]
    stp x25, x26, [x0, #48]
    stp x27, x28, [x0, #64]
    stp x29, x30, [x0, #80]
    mov x9, sp
    str x9, [x0, #96]

    ldr x9, [x1, #96]
    mov sp, x9
    ldp x19, x20, [x1, #0]
    ldp x21, x22, [x1, #16]
    ldp x23, x24, [x1, #32]
    ldp x25, x26, [x1, #48]
    ldp x27, x28, [x1, #64]
    ldp x29, x30, [x1, #80]
    ret
```

Смещения должны совпадать с `#[repr(C)]`; лучше вынести их в константы и проверять `offset_of!`.

### Новая задача

- `sp = stack_top`, выровненный на 16.
- `x30 = entry`.
- Остальные регистры — 0.
- Первый `ret` в `sched_switch` прыгнет в `entry`.

Задача должна иметь сигнатуру `extern "C" fn() -> !`; если она вернётся, нужен `task_exit`.

## Preemptive switch

Текущий IRQ-trampoline уже сохраняет на стек задачи:

```text
x0..x30, ELR_EL1, SPSR_EL1
```

и восстанавливает их перед `eret`.

Для вытеснения:

1. В IRQ-обработчике решить, что нужен switch.
2. Сохранить `SP` текущей задачи (указатель на её IRQ-кадр) в TCB.
3. Выбрать следующую задачу и взять указатель на её сохранённый IRQ-кадр.
4. Переключить `SP` на этот кадр, восстановить регистры и `eret`.

Сложность: Rust-код обработчика выполняется на стеке текущей задачи. Нельзя просто «переключить SP» внутри Rust-функции и продолжить — нужно вернуться в asm-trampoline, который и сделает переключение. Поэтому preemptive делают после cooperative, когда TCB и стеки уже отлажены.

## Подводные камни

> [!warning]
> - Неверные смещения в `TaskContext` → мгновенная порча регистров.
> - Забыли сохранить `SP` → задачи делят один стек.
> - Новая задача с `x30 = 0` → `ret` в никуда.
> - Стек не выровнен на 16 → fault/UB.
> - FP/SIMD не сохранены, но используются → тихая порча.
> - Переключение под `SpinLock` → другая задача зависнет на этом lock.
> - Preemptive switch из середины Rust-функции без asm-trampoline → потеря кадра.
