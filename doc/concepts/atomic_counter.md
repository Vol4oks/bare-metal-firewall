# Счётчик тиков: static AtomicU32

> [!abstract] Суть
> `TICKS` — глобальная переменная, которую пишет обработчик прерывания и читает `main`. Её нельзя держать в `static mut`: компилятор не знает про асинхронный вызов обработчика. `AtomicU32` с `Ordering::Relaxed` даёт атомарность без лишних барьеров — для счётчика этого достаточно.

## Почему не `static mut`

- `static mut` + `+= 1` — гонка: `main` может читать, пока IRQ пишет.
- Компилятор вправе закешировать значение в регистре и не перечитывать его в цикле.
- В Rust 2024 ссылки на `static mut` — отдельная головная боль (`static_mut_refs`).
- `AtomicU32` — фиксированный адрес + атомарные операции, компилятор обязан перечитывать.

## Код

```rust
use core::sync::atomic::{AtomicU32, Ordering};

static TICKS: AtomicU32 = AtomicU32::new(0);

pub fn ticks() -> u32 {
    TICKS.load(Ordering::Relaxed)
}

// в ISR:
TICKS.fetch_add(1, Ordering::Relaxed);
```

- `AtomicU32::new(0)` — const-инициализатор, переменная уходит в `.bss` (start.s её обнулит).
- `fetch_add` возвращает старое значение; нам оно не нужно.
- `load` в `ticks()` — единственное место чтения; `TICKS` остаётся приватным.
- `fetch_add` переполняется по кругу (wrapping), а не паникует: при 4 Гц 32 бита хватит на ~34 года.

## Ordering

| Ordering | Что гарантирует | Когда нужно |
|---|---|---|
| `Relaxed` | атомарность + единый порядок модификаций этого атомика | счётчик, статистика |
| `Acquire`/`Release` | порядок между этим атомиком и обычными load/store | флаг готовности данных |
| `SeqCst` | глобальный порядок всех SeqCst-операций | когда без него не доказать корректность |

`Relaxed` **не** создаёт happens-before для других переменных. Если счётчик станет «данные готовы, читай буфер», понадобится `Release`/`Acquire`.

## Подводные камни

> [!warning]
> - `AtomicU32` не делает всю структуру потокобезопасной — только саму переменную.
> - `Ordering::SeqCst` «на всякий случай» — лишние барьеры; для счётчика не нужен.
> - На AArch64 `Relaxed` — это обычные `ldr`/`str` (для 32-бит), а не `ldar`/`stlr`; атомарность обеспечивает сама инструкция/LL-SC.
> - Если позже появится несколько ядер, `fetch_add` останется атомарным, но порядок с другими данными всё равно надо проектировать.
