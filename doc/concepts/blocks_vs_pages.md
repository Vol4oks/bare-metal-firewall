# Блоки vs страницы и таблица регионов

> [!abstract] Суть
> Страницы нужны там, где есть гранулярная аллокация; до heap блоки дают те же атрибуты и права дешевле. Масштабирование закладывается не «страницами заранее», а табличной генерацией дескрипторов из массива регионов: новая плата = строка в REGIONS, а не переделка транслятора.

## Почему блоки, а не страницы
- Страница 4 КБ = гранулярность (мапить/размапить/правами отличать мелкие куски). Она стоит памяти (L3-таблицы) и нужна, когда памятью управляет менеджер. У нас его нет.
- Блоки несут те же атрибуты (Normal/Device, AP, PXN) — разница только в размере региона, не в возможностях.
- RAM (1 ГБ) = 1 дескриптор L1; UART (2 МБ) = 1 дескриптор L2. Страницы бы потребовали таблиц L3 без выигрыша.

## Что масштабируется на «жирную плату»
1. **Структура**: L0→L1→L2 — верхние уровни дерева; L3 включается точечно, где появится гранулярность (heap с per-page правами). Архитектура ARMv8-A не меняется.
2. **Параметры, а не архитектура**: TCR.IPS (размер PA), список регионов — конфигурация, не переделка.
3. **Генерация дескрипторов из таблицы регионов** — единственная настоящая инвестиция в рост:

```rust
const REGIONS: [Region; 2] = [
    Region { va: 0x4000_0000, size: Size1G, kind: Normal },
    Region { va: 0x0900_0000, size: Size2M,  kind: Device },
];
// init_identity_map(): L0[0] -> L1, регионы -> индексы (addr>>30, addr>>21), Table/Block-дескрипторы
```

> [!warning] Ограничения (осознанные, до heap-этапа)
> - Регионы выровнены на свой размер (иначе — дробление на страницы).
> - Регион не пересекает L1-границу (1 ГБ) — иначе смешение Normal/Device в одном блоке.
> - Смешивать атрибуты внутри блока нельзя: блок минимальная единица атрибутов на своём уровне.
