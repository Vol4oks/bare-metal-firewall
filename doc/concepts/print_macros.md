# Макросы печати: $crate, concat!, format_args!

> [!abstract] Суть
> `print!`/`println!` в no_std — тонкие обёртки: `format_args!` собирает `Arguments`, `core::fmt::write` печатает через хэндл, `concat!` вклеивает `\n` в шаблон, `$crate` делает пути устойчивыми к месту вызова.

## Три классических грабли

1. **Arguments ≠ &str.** `format_args!(...)` даёт `fmt::Arguments`; методу с `&str` его не передать (E0308). Нужен приёмник: `core::fmt::write(&mut writer, args)` (или `core::write!`).
2. **`\n` как аргумент, а не часть шаблона.** `print!($fmt, "\n")` → `format_args!("Hello", "\n")` → `argument never used`. Правильно: `concat!($fmt, "\n")` — склейка литералов на раскрытии макроса.
3. **Гигиена путей.** Пути без `$crate` резолвятся в месте вызова: `uart::UART` из crate root работает случайно, из модулей ломается (E0433). Всегда `$crate::uart::UART`. Экспортированный макрос живёт в корне крейта: `$crate::print!`, а не `$crate::uart::print!`.

## Канонический println (три руки)

```rust
($fmt:expr) => { $crate::print!(concat!($fmt, "\n")) };
($fmt:expr, $($arg:tt)*) => { $crate::print!(concat!($fmt, "\n"), $($arg)*) };
```
Три руки нужны, чтобы грамматика различала «только шаблон» и «шаблон + аргументы».

Почему `\n` оказывается именно в конце вывода: `concat!` вклеивает его в конец *шаблона*, после последнего плейсхолдера — а позиция в шаблоне = позиция в выводе (шаблон — линейный сценарий: литералы печатаются как есть, `{}` замещаются по порядку). Так же делает std через внутренний `format_args_nl!`. Нюанс: `concat!` требует строковый литерал — на практике ограничения нет, т.к. `format_args!` тоже требует литерал-шаблон.

> [!warning] Подводные камни
> - `print!()` без аргументов → `format_args!()` → ошибка; добавьте пустую руку, если нужно.
> - `#[macro_export]` поднимает макрос в корень крейта; из модулей — `crate::print!` или `use crate::print;`.
> - `macro_rules` текстуален: без `#[macro_export]` макрос виден только ниже своего определения.
