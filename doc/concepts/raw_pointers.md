# Работа с сырыми указателями в Rust

> [!abstract] Суть
> Сырой указатель = адрес без обещаний: может быть null, может алиаситься, компилятор не проверяет. Разыменование — только в `unsafe`. Для MMIO — только через `read/write_volatile`; для обычной памяти (heap) — простые `*p` достаточно.

## Типы
- `*const T` — адрес, только чтение; `*mut T` — чтение и запись.
- Отличие от `&T`: ссылки валидны всегда (и `&mut` эксклюзивен), указатели — нет. Отсюда: разыменование `unsafe`, проверка null — на программисте.

## Операции

| Операция | Пример | Применение в проекте |
|---|---|---|
| число → указатель | `addr as *mut u8` | регистры, heap |
| адрес без ссылки | `&raw const X` / `&raw mut X` | символы линкера, statics |
| чтение/запись | `unsafe { *p }` / `*p = v` | heap, состояние аллокатора |
| volatile | `p.read_volatile()` / `write_volatile` | только MMIO ([[mmio_basics]]) |
| сдвиг | `p.add(n)` — в единицах T; `p.byte_add(n)` — байты | индексация таблиц |
| смена типа | `p.cast::<u64>()` | PageTable как u64 |
| указатель → число | `p as usize` | печать адресов |
| «нет значения» | `core::ptr::null_mut()` | отказ в GlobalAlloc::alloc |
| указатель → ссылка | `&mut *p` | работа с statics через &raw mut |

## Правила безопасности
1. Разыменование — только валидный, выровненный указатель.
2. `&mut *p` — обещание эксклюзивности; для statics держится инвариантом «одно ядро, IRQ замаскированы» ([[0002_global_uart_handle]], [[multicore_path]]).
3. null — проверять до разыменования; в `alloc` null — легальный «памяти нет» ([[global_alloc]]).

> [!warning] Подводные камни
> - `p.add(n)` сдвигает на n **элементов** T, не байт: для `*const u64` шаг 8.
> - Volatile на обычной памяти не нужен и вредит (запрещает легальные оптимизации).
> - Два `&mut` из одного указателя = UB (алиасинг) — см. кейс паники в печати.

> [!question] Самопроверка
> - Чем `p.add(1)` для `*const u64` отличается от прибавления 1 к `usize`-адресу?
> - Почему `&raw const` лучше `&x as *const _` для extern-статиков?
