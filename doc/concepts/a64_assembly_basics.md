# A64 ассемблер: минимум для чтения start.s

> [!abstract] Суть
> Ассемблер — язык «одна строка = одна машинная инструкция»: нет переменных, только регистры и память. Здесь — подмножество A64 и синтаксиса GNU as, достаточное для чтения `src/start.s`, плюс режимы адресации, на которых чаще всего спотыкаются.

## Регистры AArch64

| Регистр | Роль |
|---|---|
| `x0`–`x30` | 64-битные регистры общего назначения; `w0`–`w30` — их младшие 32 бита (запись в `w` обнуляет верхнюю половину) |
| `xzr`/`wzr` | аппаратный регистр-ноль: чтение = 0, запись = в никуда |
| `sp` | указатель стека — отдельный регистр, не часть x-набора |
| `x30` (`lr`) | link register: `bl` кладёт сюда адрес возврата |
| `x0`–`x7` | аргументы/возврат по AAPCS64 (соглашению вызовов) |

Системные регистры (`mpidr_el1`, `sctlr_el1`, …) доступны только через `mrs` (чтение) и `msr` (запись).

## Синтаксис GNU as

- Метки `1:`, `2:` — локальные числовые; ссылка `1b` — ближайшая **назад** (backward), `2f` — ближайшая **вперёд** (forward).
- Директивы не генерируют код: `.section .text._start` — в какую секцию класть, `.global _start` — экспорт символа для линкера.
- Комментарии — `//`.
- Имя файла `.s` — конвенция раннего Unix (`as` = ассемблер). Действующее различие в gcc/clang: `.S` (капитал) = прогнать через cpp. Для Rust `include_str!`/`global_asm!` расширение — только метка для читателя: rustc получает строку.

## Директивы построения таблицы векторов (этап 3.1)

| Директива | Что делает |
|---|---|
| `.section .vectors, "ax"` | сменить секцию: a → в LOAD-сегмент, x → executable |
| `.align 11` | выровнять на 2^11 = 2048 байт — **аргумент = степень двойки** (AArch64 GNU as) |
| `.balign 2048` | то же, но аргумент — байты |
| `.global имя` | экспорт символа — без него невидим из Rust |
| `метка:` | символ по текущему адресу счётчика |
| `.space 124` | N байт нулей (синоним `.skip`) |
| `.rept N` / `.endr` | повтор блока N раз |
| `.macro` / `.endm` | макрос, параметр через `\имя` |

Единственная инструкция в таблице на этом этапе — `b` (4 байта, PC-relative, ±128 МБ). Именно `b`, не `bl`: `bl` затёр бы `lr` прерванного кода.

Одинаковые слоты штампуются циклом сборки — `.rept 16` + `SLOT unexpected`. Это разворачивание в тексте, не runtime: в бинаре по-прежнему 16 копий. Когда слоты разойдутся (3.2: 4 рабочих + 12 заглушек) — `.rept 4` + 4 явных + `.rept 8`.

```asm
.macro SLOT handler
    b \handler
    .space 124
.endm

.align 11
.global irq_vectors
irq_vectors:
    SLOT unexpected
    // ... всего 16 слотов = 0x800 байт
```

> [!warning] Ловушки
> - `.align` на AArch64 — степень двойки; в linker-скрипте `ALIGN(2048)` — байты. Путаница классика.
> - Паддинг-нули в слоте безопасны: исполнение всегда начинается с начала слота и `b` уводит его. Ноль в *начале* слота = UDF.
> - Forward-ссылка `b unexpected` допустима: ассемблер двухпроходный, адрес проставит линкер релокацией.

## Инструкции start.s

| Инструкция | Что делает | Зачем здесь |
|---|---|---|
| `mrs x0, mpidr_el1` | прочитать системный регистр | узнать «кто я» ([[entry_hygiene]]) |
| `and x0, x0, #3` | побитовое И (маска) | оставить биты Aff0 |
| `cbnz x0, park` | если ≠ 0 — перейти | сравнение + ветвление одной инструкцией |
| `msr daifset, #0xf` | установить 4 маски исключений (D/A/I/F) | `#0xf` — битовое множество масок, не число |
| `ldr x0, =stack_top` | **адрес** символа через literal pool | псевдоинструкция; `mov` такой immediate не кодирует |
| `mov sp, x0` | записать `sp` | в `sp` нельзя загрузить через `ldr =` |
| `cmp x0, x1` | вычитание без записи результата | установка флагов для условных ветвлений |
| `b.hs 2f` / `b.lo 1b` | переход по **unsigned** ≥ / < | hs/lo — беззнаковые, ge/lt — знаковые |
| `stp xzr, xzr, [x0], #16` | записать пару регистров (16 байт нулей), затем `x0 += 16` | post-index — см. ниже |
| `bl main` | переход + адрес возврата в `x30` | вызов функции |
| `wfi` | спать до прерывания | парковка ядра без активного кручения |

## Системные регистры из Rust: core::arch::asm!

`msr`/`mrs` принимают **только GP-регистр**, не immediate. Адрес в регистр кладут операнды asm!, а не хардкод:

```rust
let readback: usize;
unsafe {
    core::arch::asm!(
        "msr vbar_el1, {v}",   // {v} — дырка, rustc подставит имя регистра
        "mrs {r}, vbar_el1",
        v = in(reg) table,     // вход: значение кладётся в свободный регистр
        r = out(reg) readback, // выход: содержимое регистра → переменная
    );
}
```

- `in(reg)`/`out(reg)` — договор: компилятор сам выбирает регистр и учитывает его занятым. Хардкод `x0` опасен: компилятор не знает, что вставка его трогает.
- `unsafe` здесь — обещание «я знаю, что меняю состояние CPU»; unsafe-блок локализуют внутри безопасной функции, а не вешают на весь API.
- Барьеры `dsb/isb` нужны, когда состояние влияет на исполнение при живых событиях (включение MMU); для записи VBAR при замаскированных исключениях не требуются. Подробнее — [[memory_barriers]].

> [!warning] MRS/MSR и имена регистров
> - В AArch64 **нет** `mrc`/`mcr` — это инструкции AArch32. Чтение: `mrs Xt, <sysreg>`, запись: `msr <sysreg>, Xt`.
> - Имя системного регистра должно совпадать с Arm ARM посимвольно: `icc_igrpen1_el1`, а не `icc_igroen1_el1`. Опечатка даёт ошибку ассемблера `expected writable system register or pstate`.
> - Для PSTATE-полей (`daifset`, `daifclr`, `spsel`) форма особая — там immediate (`msr daifclr, #2`), а не GP-регистр.

## Режимы адресации stp/ldr

```text
[x0]          адрес в x0
[x0, #16]     адрес x0+16, x0 не меняется
[x0, #16]!    сначала x0 += 16, операция по x0 (pre-index)
[x0], #16     операция по x0, потом x0 += 16 (post-index)
```

> [!warning] Подводные камни
> - **Post-index `[x0], #16` ≠ offset `[x0, #16]`**: первый пишет по x0 и сдвигает регистр, второй пишет по x0+16 и ничего не меняет. В bss-цикле замена post-index на offset = бесконечный цикл: x0 застывает, `b.lo 1b` всегда истинно, до `main` дело не доходит, а первые 16 байт `.bss` остаются мусором.
> - `b.hs`/`b.lo` (unsigned) vs `b.ge`/`b.lt` (signed): адреса всегда сравниваются беззнаково.
> - `ldr x0, =symbol` грузит **адрес**; `ldr x0, [x0]` — **значение** по адресу в регистре. Почему нельзя `mov x0, stack_top`: каждая инструкция A64 жёстко 32 бита — полный 64-битный адрес в immediate не влезает. Ассемблер кладёт адрес в literal pool рядом с кодом и читает его PC-relative (альтернатива — 4 инструкции movz/movk).
> - `xzr` — не «обнулятор памяти», а источник нулей: обнуление делает сам факт записи через `stp`.

> [!question] Для самопроверки
> - Чем `stp xzr, xzr, [x0], #16` отличается от `stp xzr, xzr, [x0, #16]`?
> - Почему `ldr x0, =stack_top` нельзя заменить на `mov x0, stack_top`?
> - Почему `msr daifset, #0xf` маскирует всё, если исключений четыре?
