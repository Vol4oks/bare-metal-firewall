# USB-UART консоль платы

> [!abstract] Суть
> Консоль — единственный канал наблюдения на этапе bring-up: молчание в ней — симптом трёх разных причин (адрес, EL, UART), поэтому сначала проверяется сама линия. Адаптер CH340G, 3.3 В, 8N1, скорость по умолчанию 1500000; при мусоре — первым делом проверить скорость, при тишине — перепутанные TX/RX и GND.

## Подключение

| Сигнал адаптера | Пин платы | Замечание |
|---|---|---|
| GND | GND | подключать первым |
| TXD | RXD | перекрёстно |
| RXD | TXD | перекрёстно |

> [!warning] Электрика
> - Логика **3.3 В**, не 5 В. У CH340G бывают версии с переключателем 3.3/5 В — проверить перемычку.
> - `VCC` адаптера к плате не подключать: плата питается отдельно. Два источника питания на одной линии — способ сжечь адаптер или плату.
> - GND обязателен: без общей земли линия ловит мусор.

## Хост: команды

```bash
# как называется устройство
ls -l /dev/serial/by-id/
dmesg | grep -i ch341

# права: пользователь должен быть в группе dialout (нужен перелогин)
sudo usermod -aG dialout "$USER"
```

Открыть консоль:

```bash
picocom -b 1500000 /dev/ttyUSB0
# выход: Ctrl-A Ctrl-Q; справка: Ctrl-A Ctrl-H
```

Альтернативы: `minicom -D /dev/ttyUSB0 -b 1500000`, `tio -b 1500000 /dev/ttyUSB0`.

Запись лога — то, что нужно для разбора вывода:

- `picocom`: `Ctrl-A Ctrl-L` включает/выключает запись; в новых версиях спрашивает имя файла, иначе пишет `picocom.log` в текущий каталог.
- `minicom`: `-C uboot.log`.
- без терминала (надёжный вариант для «поймать баннер и скопировать»):

```bash
stty -F /dev/ttyUSB0 1500000 raw -echo
cat /dev/ttyUSB0 | tee uboot-h0a.log
```

> [!tip] Лучше лог, чем скриншот
> Баннер U-Boot содержит половину фактов H0 (`DRAM:`, `Loading Environment from …`, `Net:`, `MMC:`). Лог в файл позволяет искать по нему и не перепечатывать вручную.

## Проверка адаптера без платы (loopback)

Отделить «плата молчит» от «адаптер не работает»:

1. Отключить от платы TX/RX (GND можно оставить).
2. Замкнуть **TX и RX самого адаптера** перемычкой/пинцетом.
3. В открытом picocom набрать несколько символов.

| Результат | Вывод |
|---|---|
| символы возвращаются | адаптер, драйвер и терминал исправны → искать причину на плате/в проводах |
| тишина | проблема на стороне хоста: порт, драйвер, права, сам адаптер |

> [!tip] Local echo выключен
> В picocom по умолчанию `local echo is : no`, поэтому возврат символов означает именно прохождение через линию, а не отрисовку нажатий.

## Диагностика по симптому

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| «кракозябры», отдельные символы | не та скорость | попробовать `115200`, затем `1500000`; убедиться, что нет flow control |
| полная тишина, `lsusb` видит адаптер | RX/TX не перекрёстнуты, нет GND, плата не стартует | проверить провода, питание, светодиоды; затем Maskrom |
| тишина, адаптер не виден в `lsusb` | кабель/драйвер/порт | другой кабель (не «charge-only»), другой USB-порт |
| текст есть, но ввод не проходит | TX платы не доходит до RX адаптера | поменять местами TX/RX |
| символы `ñ`, `ÿ` на старте | несовпадение скорости на части вывода | U-Boot мог переключить скорость; смотреть лог целиком |

> [!warning] CH340 и 1500000
> 1.5 Мбод — верхняя граница для многих клонов CH340. Если на этой скорости поток рвётся, а на 115200 стабилен, дело в адаптере, а не в плате.
