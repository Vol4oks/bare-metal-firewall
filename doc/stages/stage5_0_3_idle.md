# Шаг 0.3: idle-задача и выход

> [!abstract] Суть
> Idle становится **настоящей задачей** с самым низким приоритетом, а планировщик — основным циклом исполнения: `main` больше не крутит `loop { print; wfi }`, он спавнит idle и уходит в `scheduler::run()`. `exit()` при пустой очереди теперь переключается в idle через `sched_start`, а не в самодельный `wfi`-цикл. Тики печатает idle после пробуждения — это одновременно и проверка, что `wfi` работает.

## Что меняется

| Было (0.2) | Стало (0.3) |
|---|---|
| `main` крутит `loop { print ticks; wfi }` в обычной сборке | `main` спавнит idle и вызывает `run()` |
| `exit()` при `None` — локальный `loop { wfi }` | `exit()` уходит в idle-задачу |
| `schedtest::run()` сам вызывает `scheduler::run()` | `schedtest::spawn_tasks()` только спавнит задачи |
| тики печатает `main` | тики печатает idle после `wfi` |
| `timer::ticks` под `allow(dead_code)` | используется всегда — allow снимается |

## Почему idle — задача, а не особое состояние

Вариант «`current == None` значит idle» требует отдельного пути в `run`/`exit` и отдельного asm-перехода. Задача дешевле:

- переиспользуется тот же `sched_start`/`sched_switch`;
- idle участвует в приоритетах как обычная задача;
- в 0.4 он сможет проснуться по событию и сделать `yield_now` — без специального кода.

Цена: один слот из `MAX_TASKS = 8`. Пока это нормально.

## Приоритет

`Prio::IDLE = 255` — самый низкий (у нас «меньше = выше»). Строгий приоритет гарантирует: idle выбирается только когда ни одна другая задача не `Ready`. Если дать idle обычный `CP`, он начнёт конкурировать с задачами по round-robin.

## Стек

```rust
const STACK_SIZE: usize = 8 * 1024;

#[repr(align(16))]
struct Stack([u8; STACK_SIZE]);

static mut STACK: Stack = Stack([0; STACK_SIZE]);

pub fn stack_top() -> usize {
    core::ptr::addr_of_mut!(STACK) as usize + core::mem::size_of::<Stack>()
}
```

Восьми килобайт хватает: `println!` пишет в UART напрямую, глубоких вызовов нет. Канарейка не обязательна — idle не переключается с чужого стека, — но можно продублировать подход из `schedtest`.

Альтернатива: отдать idle **загрузочный стек** (`stack_top` из `linker.ld`, 64 КиБ). Кадры `main` после `run()` больше не нужны, так что это корректно и экономит 8 КиБ `.bss`. Но тогда размер стека idle неявно связан со `linker.ld`; для учебного шага лучше отдельный и явный.

## Код

`src/idle.rs`:

```rust
use crate::{println, scheduler, timer};

pub extern "C" fn task() -> ! {
    loop {
        unsafe { core::arch::asm!("wfi") };
        println!("ticks = {}", timer::ticks());
        scheduler::yield_now();
    }
}
```

- `wfi` просыпается по таймерному IRQ (4 Гц) — отсюда прежняя частота печати.
- `yield_now` после пробуждения — **задел на 0.4**: если событие сделало кого-то `Ready`, он получит CPU здесь. На 0.3 готовых задач нет, `next == from`, переключения не произойдёт.
- Порядок «печать, потом yield» — осознанный: тики — это часы системы, их печатаем независимо от того, будет ли переключение.

`main` (после `gic`/`timer` init и `daifclr`):

```rust
let top = idle::stack_top();
scheduler::spawn(idle::task, "idle", scheduler::Prio::IDLE, top).expect("idle slot");

#[cfg(feature = "schedtest")]
schedtest::spawn_tasks();

scheduler::run();
```

- `spawn` идёт **до** `run()`: `start()` должен найти хотя бы idle.
- IRQ обязаны быть включены до `run()`: иначе первый `wfi` в idle заснёт навсегда.
- Старый `#[cfg(not(feature = "schedtest"))] loop { … }` удаляется целиком.

`schedtest` меняет сигнатуру:

```rust
pub fn spawn_tasks() {
    // init_stack × 3, spawn × 3 — без scheduler::run()
}
```

## `None` в `exit()` и `run()`

Пока idle существует, `exit_current()` и `start()` **всегда** возвращают `Some`: idle либо `Running`, либо `Ready`. Ветки `None` остаются только как защита от будущих ошибок (`halt()` = `loop { wfi }`). Не удаляйте их, но и не считайте достижимыми.

## DoD

- `cargo run` → тики печатаются ~4 раза в секунду, значения растут, первая строка появляется примерно через 250 мс;
- `cargo run --features schedtest` → `switch ok`, `canary ok`, затем idle печатает тики (доказывает путь `exit → idle`);
- `cargo run --features selftest` → policy-тесты, затем тики из idle;
- clippy чист во всех четырёх конфигурациях, `fmt` чист;
- `timer::ticks` больше не под `allow`, TODO у модульного allow меняется на 0.4.

## Как проверять, что CPU действительно спит

- Если `wfi` не работает (IRQ замаскированы или `wfi` вырезан), idle начнёт печатать **одно и то же** значение `ticks` тысячи раз в секунду. Признак: строки идут плотно, числа не меняются.
- Если всё правильно — ровно одна строка на тик, числа монотонно растут.
- Дополнительно: временная задача, которая никогда не выходит и делает `yield_now` в цикле, должна **лишить idle CPU** (тики перестают печататься). Это доказывает, что idle выбирается только при пустой очереди.

## Ловушки

> [!warning]
> - `wfi` при замаскированных IRQ не «спит», а крутится (см. [[0009_hybrid_scheduling]]); в idle это выглядит как шторм одинаковых `ticks`.
> - `Prio::CP` для idle → конкуренция с рабочими задачами по round-robin вместо «только когда пусто».
> - Слишком маленький стек idle → порча при `println!`; 8 КиБ — разумный минимум.
> - `exit()` из последней задачи при отсутствии idle-задачи вернёт `None`; не удаляйте защитный `halt()`, пока не уверены в инварианте.
> - Печать из idle берёт UART-lock. В 0.4 задача может спать, удерживая lock, — idle зависнет на нём. Критические секции не должны пересекать `wait`.
> - Первая строка `ticks` появляется с задержкой до одного периода таймера — это нормально, а не «зависание после VBAR».

## Дальше: 0.4

Idle уже содержит точку `yield_now` после `wfi`. В 0.4 добавляются `READY`/`PENDING`, `wake_from_isr`, `wait` с защитой от гонки, и таймер начинает будить конкретную CP-задачу, а не только idle.
